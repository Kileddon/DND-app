# Tabletop Companion — Local Table Alpha

Локальный помощник для настольной ролевой игры. Windows-ноутбук ведущего хранит данные в SQLite и обслуживает интерфейсы ведущего и игроков в одной доверенной Wi‑Fi сети. После первоначальной установки интернет для игры не нужен.

Текущая alpha включает двухшаговое подключение по QR (необязательный QR Wi‑Fi и QR лобби), локальные профили и персонажей, жизненный цикл сессии, realtime-синхронизацию и базовый цикл боя. Ведущий может безопасно загрузить портрет монстра: изображение до 8 МБ сохраняется только в локальной медиатеке.

В интерфейсе доступны выбор расы, класса и классовых способностей, HP и класс брони персонажа, переходы между лобби, карточкой и боем. Ведущий может исключать игроков, просматривать и редактировать карточки персонажей, а также вести заметки кампании, каталог неигровых персонажей и прочие заметки. Код восстановления удалён: исключённый или новый клиент подключается заново по приглашению ведущего.

Броски кубиков вынесены в отдельный раздел и доступны независимо от боя. У игрока отдельные разделы «Лобби», «Кабинет», «Персонаж» и «Кубики»; экран боя ему не показывается. Есть быстрые `1d20`, `1d6`, `1d4`, `1d100`, конструктор количества кубиков, граней и бонуса, а также взаимоисключающие режимы обычного броска, преимущества и помехи. Сервер определяет результат; приватные, секретные и отложенные броски не попадают в снимки и replay посторонних участников.

Карточка персонажа v2 поддерживает 12 классов, 7 рас с обязательными вариантами, стандартный набор, `4d6` без меньшего и point-buy на 27 очков, произвольную предысторию, четыре раунда выбора карточек способностей, архив и восстановление. Инвентарь учитывает точный вес и слоты экипировки. Ведущий может заранее подготовить несколько энкаунтеров, но одновременно активен только один; изменения HP и переносимых состояний боя синхронизируются с карточкой персонажа атомарно.

## Запуск на Windows

Нужны Windows 10/11, PowerShell, Git, [uv](https://docs.astral.sh/uv/) и Node.js 22+.

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-host.ps1
```

Откройте `http://127.0.0.1:8000` на компьютере ведущего. LAN-адрес для игроков показан в диагностике. Чтобы принудительно пересобрать web-клиент:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-host.ps1 -RebuildFrontend
```

Первый запуск создаёт `data/`, локальный секрет, SQLite БД и применяет миграции. Перед миграцией непустой файловой БД создаётся timestamped backup через SQLite backup API.

## Как провести бой

1. Ведущий создаёт комнату, приглашает игроков и переводит сессию в `ACTIVE`.
2. Игроки выбирают персонажей. Ведущий создаёт бой, добавляет выбранных персонажей и шаблоны/группы монстров.
3. После старта ведущий переключает ходы, применяет урон, лечение, временные HP и состояния. Несколько целей изменяются одной транзакцией.
4. Игрок видит точные HP только своего персонажа; для монстров отображается словесная категория ранения.
5. Участники делают публичные/приватные броски и отправляют заявки поддержки. Ведущий также может делать секретные, отложенные, массовые и физические броски через API.
6. Ошибочное действие здоровья отменяется компенсирующим событием или исправляется атомарной парой «компенсация + новое действие».
7. После завершения боя отчёт вычисляется из append-only журнала.

## Локальная сеть и безопасность

LAN-режим использует HTTP/WS и предназначен только для доверенной частной сети. Не публикуйте порт в интернет и не используйте публичную Wi‑Fi сеть. Разрешайте Python в Windows Firewall только для частных сетей. Телефон и ноутбук должны быть в одной сети без client isolation.

Долгоживущие credentials не передаются в URL. Одноразовый QR-секрет находится во fragment URL и обменивается на отзываемый HttpOnly/SameSite credential. Пароли комнат хешируются Argon2, остальные секреты хранятся как HMAC digest. Пароль Wi‑Fi используется только для построения QR в памяти: он не сохраняется и не выводится в диагностике или ответах API. Подробнее: [модель угроз](docs/security.md) и [ADR-0005](docs/adr/0005-https-lan-security.md).

## Настройка

Локальный `.env` при необходимости создаётся из `.env.example`:

```dotenv
TTC_DATABASE_URL=sqlite:///data/tabletop_companion.sqlite3
TTC_HOST=0.0.0.0
TTC_PORT=8000
TTC_LOG_LEVEL=INFO
TTC_HOST_SECRET_PATH=data/host-secret.key
TTC_FRONTEND_DIST=frontend/dist
```

OpenAPI доступен на `http://127.0.0.1:8000/docs`, health check — `/health`.

## Разработка и проверки

Backend, из корня:

```powershell
uv sync --locked --all-groups
uv run ruff format --check .
uv run ruff check .
uv run mypy src tests
uv run pytest tests/unit
uv run pytest tests/integration
uv run pytest
```

`uv` хранит кэш в локальном `.uv-cache`, а pytest — временные данные в `.test-tmp`, поэтому стандартные проверки не требуют доступа к системным каталогам. Если host уже запущен и держит исполняемый файл, проверки можно запускать с `uv run --no-sync ...` либо после остановки host.

Frontend:

```powershell
Set-Location frontend
npm ci
npm run format:check
npm run lint
npm run typecheck
npm run test
npm run build
npm run e2e
```

## Известные ограничения

- Нет облачных аккаунтов/синхронизации, общего TV-экрана, сцен и автоматизации правил действий монстров.
- Базовый UI намеренно не открывает все расширенные параметры API: ручной override категории ранения, редактирование/раскрытие броска и полная коррекция события пока доступны через OpenAPI.
- HTTPS/PWA и Windows installer отложены; физические мобильные устройства требуют ручной проверки.
- Завершённые бои сохраняются, но отдельный экран архива и сравнение отчётов ещё не реализованы.
