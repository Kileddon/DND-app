# ADR-0006: состояние боя и компенсирующие события

## Статус

Принято.

## Контекст

Бою нужны быстрые текущие проекции для интерфейса, полный аудит действий и безопасное исправление ошибок без переписывания истории.

## Решение

Использовать не полный event sourcing, а транзакционную пару:

- нормализованные таблицы хранят актуальное состояние боя, участников, состояний и бросков;
- `game_events` остаётся append-only журналом и источником итогового боевого отчёта;
- каждое изменение состояния, событие и idempotent command result фиксируются одной транзакцией;
- отмена health-события создаёт обратные фактические дельты и отдельную запись связи компенсации;
- коррекция проверяет optimistic versions до изменений и атомарно сохраняет компенсацию и заменяющее событие;
- уникальная связь исходного события с компенсацией делает повторную отмену детерминированной ошибкой;
- role-aware projection удаляет точные HP чужих персонажей и монстров до HTTP/WS выдачи.

## Последствия

Интерфейс читает текущие данные без проигрывания всей истории, а аудит и отчёт остаются воспроизводимыми. Новые виды обратимых действий потребуют явно определить их обратную фактическую дельту; универсальный механизм undo намеренно не вводится.
